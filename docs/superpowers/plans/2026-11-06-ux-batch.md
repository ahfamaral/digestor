# UX Batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every bug and make every improvement from the 2026-11-06 UI/UX review, with the owner's decisions, so the app reads clearly from Sessions to Export.

**Architecture:** Small, independent tasks, each grouped by screen so one reviewer can judge it. Logic that can be pulled out of components goes in `apps/web/lib/*.ts` with vitest tests (web tests run in `node`, no DOM); every visible change is checked in Chrome with the `digestor-run` skill on freshly seeded sessions, which are deleted afterwards.

**Tech Stack:** Next.js 16 App Router (Cache Components), Drizzle/Postgres (`packages/core`), pg-boss worker (`apps/worker`, runs in Docker), vitest, Tailwind tokens from `apps/web/app/globals.css`, Base UI via shadcn.

**Spec:** `docs/superpowers/specs/2026-11-06-ux-batch-design.md` (read it first; "Owner decisions" are binding).

## Global Constraints

- Follow `.claude/skills/digestor-ui/SKILL.md` (tokens, semantic colours, copy in `apps/web/messages/en.ts` via `t()`, keyboard, a11y) and `.claude/skills/nextjs16-gotchas/SKILL.md`.
- No "→" glyph anywhere in copy (owner).
- Approved moments are never hidden by a Briefing filter (owner).
- No re-check of moment checks after a trim (owner): no new model calls in this batch, except where an existing call is already made.
- User-facing errors are friendly sentences; raw errors go to logs only.
- One-click actions that change data get a `ConfirmDialog` (owner rule); downloads don't.
- `@digestor/core/server` only in server code. Worker code and its tests run in the container (`pnpm test:worker`); never call ffmpeg/yt-dlp on the host.
- Commit per task on branch `ux-batch` (from `home-page`). Never commit `.env`, `data/`, `node_modules`, `.pnpm-store`. Merging needs the owner's word.
- Real-app checks only on sessions you seed for the check; delete them (DB row + `data/<id>/`) when the check is done. Never touch the owner's sessions 7433d1c6, f2fce3ea, b3e26a69, a8037dcf except to look (read-only GET).

## Review Focus

1. A session with 0 clips, with 1 clip, and with 13 clips: Prepare's index, "For all clips" strip and Export's "Download all" all behave (no empty zip, no dead buttons).
2. A clip whose video was removed (`videoRemoved`, R30): "For all clips" never edits it (409 path), Download all still offers what is stored.
3. Mobile 390 px: the new strip, index, banner and dialogs don't overflow; tap targets ≥ 32 px (Approve/Skip ≥ 40 px).
4. Keyboard: the sticky clip index, collapsible cards, Sources disclosure and Download-all dialog are reachable and operable with Tab/Enter/Escape, focus visible.
5. Content in other scripts (Portuguese accents, German ß, Cyrillic) in titles and subtitle lines keeps `lang`/`dir="auto"` in every new place it appears; zip file names use an ASCII fallback.
