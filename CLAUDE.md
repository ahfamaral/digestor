# Digestor

Long public-interest videos (interviews, parliament, UN, trials) → subtitled clips. Turing College capstone. All TypeScript (strict, ESM), pnpm monorepo:

- `packages/core`: zod domain schemas, profiles and highlight types (`profiles.ts`), time/snap logic, subtitle text (`subtitleText.ts`), Drizzle tables + repo functions, LocalStorage, queue names and `JOB_OPTIONS`.
- `apps/worker`: pg-boss consumer, own step runner (`src/pipeline/run.ts`, position in `pipeline_runs`, one human pause: the context check; `match_record` runs before it and `match_record_late` after it, so a suggestion accepted at the pause is matched on Continue), analysis agents (topics, moments, briefing, checks), Ask, Chroma search index, AssemblyAI, Claude via LangChain, ffmpeg, yt-dlp, retention clean-up and stale-session sweep, evaluation (`src/eval`, `scripts/eval.ts`).
- `apps/web`: Next.js 16 (App Router, Cache Components, Turbopack): screens + API routes + SSE.

## The journalist flow

Stepper: Upload › Processing › Context › Briefing › Prepare › Export. Routes: `/` (Sessions: every video with where it is, type tabs, filters, clips; `components/Home/`, `lib/home.ts`), `/new` (upload), `/s/[id]` (Processing, Context check, then the Briefing page once `ready`: a summary card on top, then one card per topic with its moment tree, level checkboxes and Approve / Skip; `components/Briefing/`, loaded by `lib/briefingPage.ts`), `/s/[id]/prepare`, `/s/[id]/export`, `/reports`. `/s/[id]/briefing` redirects to `/s/[id]` with its query string (`next.config.ts`). The Ask drawer opens with `/` on the Briefing page; there are no letter shortcuts. A moment is Approved or Skipped (stored as `rejected`), or undecided; clicking the active status undoes it.

- Stages (`schemas.ts`): `uploaded`, `downloading`, `preparing`, `transcribing`, `understanding`, `awaiting_context`, `naming_speakers`, `indexing`, `finding_topics`, `finding_moments`, `writing_briefing`, `preparing_preview`, `ready`, `failed`. A first analysis ends in `preparing_preview` (96) and the session becomes `ready` only when the 360p preview copy (`proxy.mp4`, its own job; `sessions.proxy_status`) is done too: `settlePreview` closes that join from whichever side finishes last. Until the copy exists the context check and Who's who play voice samples from `audio.mp3`; once the session is `ready`, `audio.mp3` is deleted and `audio_key` cleared (`releaseAudio` after the join; the daily `maintenance.cleanup` catches leftovers). Only transcription reads it.
- Profiles (`profiles.ts`): `parliament`, `supreme_court`, `electoral_debate`, `trial` (sensitive), `interview`, `un`, `other`. Each profile lists its highlight types; a type is `ai` or `counted` (`longest_speech`). The chip colour comes from `HIGHLIGHT_TYPES[*].tone` via `components/HighlightChip.tsx`.
- An analysis is a versioned set of topics, moments (granularity `exchange` / `passage` / `punchline`), highlights and a briefing; selections, clips and subtitle tracks are a personal layer (`owner_id`, `OWNER_ID = "owner"`). Selections belong to one analysis version's moments: after a re-analysis they no longer show (the Briefing page counts them per version), while clips and their subtitle tracks keep working.
- Queues (`packages/core/src/queue.ts`, all with `JOB_OPTIONS`): `session.start`, `session.resume`, `session.reanalyze`, `moment.check`, `track.prepare`, `track.burn`, `clip.render`, `briefing.translate`, `ask.run`, `moment.find_more`, `session.proxy` (encode the preview copy; the runner transcribes without waiting for it), `session.names` (match a linked official record of the Câmara, Senado, Bundestag, US House or US Senate; rows are `suggested` (YouTube suggester, accepted by the journalist), `pending`, `running`, `waiting` (not published yet, `records.retry` looks again), `matched` or `failed`; at upload the runner's `match_record` step does it before the context check); scheduled in the worker: `session.sweep` (every 15 min), `maintenance.cleanup` (daily) and `records.retry` (hourly: claims `waiting` official-record rows whose `retry_at` is due, every 6 h, and sends `session.names`).
- Retention: `VIDEO_RETENTION_DAYS` (default 14) deletes `original.*`, `audio.mp3`, `proxy.mp4`, the pipeline run row (`pipeline_runs`, holds the context answers) and the session's Chroma index (so Ask search stops working after 14 days); analyses, personal layers and rendered clips stay. The sweep fails sessions and analysis versions with no progress for 120 minutes, and job rows stuck for 30 minutes (below).
- Chroma is live: one collection per session (`session_<uuid without dashes>`) with a transcript index for Ask, using local `Xenova/multilingual-e5-small` embeddings cached in `data/models` (`HF_HOME`).

## Câmara monitor (preview)

Official records of the Brazilian Câmara (deputies, plenary speeches, roll-call votes since 1 Feb 2026), separate from the journalist flow. Specs `docs/superpowers/specs/2026-11-11-camara-monitor-preview-design.md` and `2026-11-11-monitor-search-filters-design.md` (the workspace round).

- Routes (all URL state parsed and built in `lib/monitor/params.ts`, client-safe; invalid values are ignored, never a 500):
  - `/monitor`: two doors. A deputy combobox (`DeputyCombobox`, Base UI, `GET /api/monitor/deputies?q=` → `{ rows, more }`, 2+ letters, 8 shown) opens the deputy's page; a topic search (`GetForm`: empty fields are not sent; an empty topic shows a hint) with `q, exact=1, show (speeches|rollcalls), from, to, party, uf (on the day), phase, inOffice=1 (these four: speeches only), sort=new, year, p, rp`, then a counts line jumping to each group.
  - `/monitor/deputados`: every deputy without typing (`DirectoryView`, `lib/monitor/directory.ts`): in office by default, `party, uf` (today's), `former=1` adds those not in office; grouped by first letter (accents ignored) with a sticky letter row; alphabetical only, no activity counts or ranking. Linked as "Browse all deputies (N)" under the landing's name box, "All deputies" beside the deputy page's box, and from the combobox panel when clicked with under 2 letters.
  - `/monitor/deputados/[id]` (Câmara deputy id): header with profile line, a sticky "On this page" row (`SectionNav`), party timeline (dates listed at every width), positions, speech search `q, exact=1, rel=mentions (others' speeches naming them; topic optional), from, to, phase, sort, p` (20 a page), authored bills `btype, bp` (type codes explained, `lib/monitor/billTypes.ts`), recorded votes `vp` (20 a page; the motion first, "Vote on a request" marked by `lib/monitor/votes.ts`), presence ("Present at N of M…", never a %, a ranking or "absent"), fronts. Speeches and votes are never paired.
  - `/monitor/votacoes/[id]` (votação id `\d+-\d+`): votes grouped by the party at the time of the vote (smallest vote group first), and the party/bloc guidance. `?from=<deputy id>` (opened from a deputy's votes): the back link names them, their vote shows under the header and their row is marked; `?back=<a /monitor search URL>` (validated, `backToSearch`): the back link returns to that search.
  - In-page navigation never leaves an `#anchor` in the address (Chrome would jump to it on Back instead of restoring the position): `JumpLink`/`SectionNav` scroll without a history entry, and `ScrollToHash` lands on a link's `#section` after streaming, then removes it. `ReturnLink` goes Back (scroll restored) when the previous history entry is its target (Navigation API), else it is a plain link.
  - `/monitor/lang?to=en|pt-BR&back=` sets the `monitor_lang` cookie.
  Server components except `DeputyCombobox` and `YearSelect` (`components/Monitor/`, `lib/monitor/`); copy in `messages/monitor.ts` (`tm()`, English and Portuguese), not in `t()`. Year: only 2026 for now (`MONITOR_YEARS`).
- Tables (migration 0022): `parl_members`, `parl_speeches`, `parl_roll_calls`, `parl_votes`; stored `tsvector` columns on `pt_unaccent` (Portuguese stemming, accent-insensitive), `pg_trgm` on names. Migration 0023: `parl_member_history`, `parl_orientations`, `parl_sessions`, `parl_presence`, `parl_bills`, `parl_bill_authors`, profile columns on `parl_members`, party/UF on speeches (on the day) and votes (at the vote), a stable speech key. Migration 0024: speeches' `url_text` (the Câmara's text page, https on a Câmara host only) and `text_file` (published as an attached .docx: `text` keeps the heading only); the worker's `cleanText` maps Windows-1252 leftovers. Repo functions in `packages/core/src/db/monitor.ts` (search) and `monitorRecord.ts` (history, profile, presence, bills, roll-call detail); timeline logic in `monitorTimeline.ts` (client-safe).
- Data: `apps/worker/src/monitor/` (`camara.ts` API client, `bulk.ts` + `rollCalls.ts` bulk CSV parsers, `refreshMonitor`); queue `monitor.refresh`, daily 09:00 UTC, in this order: deputies, in-office flags, each deputy's history (`/historico`, legislature 57 rows only), the last 60 days of speeches (transcriptions arrive weeks late) and their party on the day, profiles (`/profissoes`, `/mandatosExternos`, `/frentes`, `/orgaos`: all on Mondays, else only deputies never fetched), then the year's bulk files one at a time (roll calls, votes, missing bills, guidance, plenary sessions and presence, bills and authors; a missing guidance/sessions/bills file skips its part only). API calls 4 in flight. A deputy that fails is skipped and counted (history or speeches failing for more than half throws); an empty in-office list keeps the stored flags. An empty API answer never deletes stored speeches. Presence and authorship of deputies outside the members list are skipped.
- Video evidence (migration 0025): queue `monitor.video` (worker, one session every 5 min; `scripts/monitor-videos.ts` loads sooner) takes each held plenary (`parl_session_videos`, claimed with compare-and-set; a `running` row untouched for 30 min is taken over; `no_video` / `no_captions` / `failed` wait for `retry_at`; a `done` session goes back to `pending` when more speeches have text), reads the event's `urlRegistro` (YouTube), fetches only the automatic `pt-orig` captions (`youtube/captions.ts`, no video), and places each spoken speech in it (`monitor/videoAlign.ts`: anchored on the stream's start, search ±15/25 min around the stamp for the speech's first and last words, cosine score; stored only at ≥ `VIDEO_MATCH_MIN` 0.6) in `parl_speech_videos` (speech key, video id, start/end second). Speech rows carry `video`; `SpeechVideo` loads the youtube-nocookie player only on click and links "Open on YouTube at h:mm:ss"; a speech sent in writing (`isWrittenOnly`) says it wasn't spoken. The refresh also drops copies the Câmara files under the wrong deputy (`misfiledCopies`: header party/state on the day, else the printed name).
- The only LLM call: `lib/monitor/translateQuery.ts` in the web app turns a query into ≤ 4 Portuguese terms (OpenRouter, 10 s, cached); without `OPENROUTER_API_KEY`, on failure or with `exact=1` the words are searched as typed. The terms it adds are shown as "related terms added automatically", and rows holding the typed words together rank first (`phrase`). No AI text about a person anywhere. Code never fetches `www.camara.leg.br` pages.

Spec: `docs/superpowers/specs/2026-10-28-video-digestor-design.md` (v1) and `docs/superpowers/specs/2026-10-30-digestor-ui-concept-design.md` (the journalist flow, Plan 2 onwards). Plans: `docs/superpowers/plans/`. Deploy runbook: `docs/deploy.md`. Manual real-API checklist: `scripts/smoke.md`.

## Environment

- Docker runs on **Colima** (`colima start --cpu 4 --memory 4`; this Mac has 8 GB RAM, so 8 for the VM pushed macOS into heavy swap), not Docker Desktop. `docker compose up -d` starts postgres, chroma (transcript index for Ask) and the worker; the web app runs on the host: `pnpm --filter @digestor/web dev`.
- **Never install or call ffmpeg/yt-dlp on the host** (host ffmpeg has no libass). Anything that runs them — worker code and its tests — runs in the worker container.
- API keys live in `.env` (`ANTHROPIC_API_KEY`, `ASSEMBLYAI_API_KEY`, `OPENROUTER_API_KEY`, `API_DATA_GOV_KEY` for US House/Senate records, optional `BUNDESTAG_DIP_API_KEY`); they may be empty. `LLM_PROVIDER=anthropic|openrouter` (default anthropic) picks the LLM vendor (`apps/worker/src/llm/provider.ts`); the key it needs is the one a missing-key failure names. Every structured call goes through `StructuredLLM` and Ask through `ToolLLM`, so a provider is one adapter pair; analysis versions record provider-qualified model ids (`StructuredLLM.modelIds`). Changing `.env` needs `docker compose up -d worker` (restart doesn't re-read it). The worker starts without them and fails a job with "`<VAR>` is not set on the server." when first needed. `APP_PASSWORD` empty = password gate off.
- YouTube from a server IP hits a bot check: `YTDLP_COOKIES_FILE` (a cookies.txt in git-ignored `./secrets/`, mounted read-only at `/secrets`) gets past it; see `docs/deploy.md`. yt-dlp runs that use it go through `withYouTubeCookies` (`youtube/cookieJar.ts`): one at a time, on a live jar in `<DATA_DIR>/.youtube/` that keeps YouTube's refreshed cookies and restarts from a new export. A block that exits 0 (caption fetch) is detected (`blocked`) and fails, never "no captions".
- The worker container bind-mounts the repo and runs `tsx watch`; after editing worker code over the Colima mount, `docker compose restart worker` if the change isn't picked up.

## Conventions that bite

- `@digestor/core` is client-safe; DB, repo, storage and migrate come from `@digestor/core/server`. Never import `/server` from a client component.
- Merge (`mergeClips`) is only for clips that overlap partly or touch (never a gap, never one clip inside the other: `contained`); it keeps the earlier clip, soft-deletes the later one and stores its moments in `clips.merged_moment_ids`; Undo restores both; a clip is dismissed when any of its moments is not approved.
- Relative imports inside `packages/core` use `.ts` extensions (Turbopack can't map `.js` → `.ts`); the worker uses `.js`. Keep each package's convention.
- The DB stores storage-relative keys (`<sessionId>/original.mp4`), never absolute paths; each process resolves them against its own `DATA_DIR`.
- Uploaded files are saved as `original.<ext>`; user filenames never reach ffmpeg.
- Concurrency is guarded in the database, not by pg-boss:
  - stage changes via `transitionStage` (compare-and-set);
  - `confirmClips` and `claimAnalysisVersion` run under `pg_advisory_xact_lock(hashtext(sessionId))`;
  - renders and burns use claim/finish compare-and-set (`claimClipRender` / `finishClipRender`, `claimTrackBurn` / `finishTrackBurn`); a burn or render whose cues, bounds, credit or subtitle style/position (`burnSignature`) changed meanwhile is marked `stale`;
  - Ask actions use `resolveAskAction` (compare-and-set), and Ask undo only reverts what the call itself set.
- `singletonKey` is a no-op on our standard queues: never rely on it to dedupe; claim in the database first, then send.
  - `moment.check` is claimed with `claimMomentCheck` (checks null and no claim younger than 10 min); a failed send or a job that gives up calls `releaseMomentCheck`. Ask answers are claimed with `claimAskMessage` (`pending` → `running`); a retry that finds `running` fails the message instead of repeating tool calls.
- Subtitle tracks record the clip range they were built for (`built_start_ms` / `built_end_ms`). Any bounds change (trim, extend, undo, Ask `trim_clip`) marks other-range tracks `outdated` and clears approval in the same transaction; outdated tracks have no SRT/VTT, fail the checklist and are rebuilt through `POST /api/clips/[id]/tracks` (R27).
- Moment checks describe the moment's bounds: they count for a clip only while its bounds equal the moment's (`checksForClip`); any bounds change resets `warningsAck` (R28).
- The sweep also fails job rows whose job died: translations `pending`, tracks `preparing`, renders and burns `queued`/`rendering`, "Find more" requests `pending`/`running`, record fetches `pending`/`running` (`waiting` and `suggested` are not job-owned), preview copies `pending`/`running` (`sessions.proxy_status`), untouched for 30 min with no live job matched on pg-boss job data (R32). New job-owned rows belong there too.
- The credit typed once is remembered: `clips.credit_set_at` is set only when a clip's credit changes, and `insertClip` copies the most recently set credit to new clips. Export's "Download all" is `GET /api/sessions/[id]/download?choice=burned|files|plain` (`check=1` answers `{ files }` as JSON), a zip built from stored files and cue-rendered SRT/VTT only; nothing is rendered or encoded there.
- Once a session's video is removed (`videoDeletedAt`), kept clips are frozen: clip edits, undo and track edits/approve/burn answer 409 with `VIDEO_REMOVED`; acknowledgements and downloads still work (R30).
- Ask makes at most 3 direct changes per question, counting each moment of `set_selection`, each `propose_clip` and each `trim_clip`; beyond that selections become a confirm action and clip calls are refused. Tool output built from transcript-derived text (search hits, transcript, moment titles and reasons) goes through `evidence()` (R31).
- Subtitle SRT/VTT downloads are rendered from the track's cues on every request (never stored files), and drafts stay downloadable; burn-in needs per-language approval.
- Trim: the server snaps only the edges that changed to sentence boundaries (an untouched edge, within 100 ms of its stored value, stays verbatim). `PATCH /api/clips/[id]` with `free: true` (Alt/Option drag or Alt+arrows in the UI) saves the exact position; the clip then carries `midSentence` (checks are null, so it needs `warningsAck`).
- Approved moments are never hidden by filters: the briefing footer reads "N approved · M hidden by filters" with a "Show hidden" button.
- AI and normal cuts snap to sentence boundaries (sentence ends, or a pause inside a very long sentence); an Alt cut is saved as is and carries a mid-sentence warning. Every boundary except a deliberate Alt cut goes through `snapRange`/`snapEdges`; Extend, Ask `trim_clip`, normal drags and the typed fields still snap.
- Claude 5.5 (`claude-sonnet-5-5`, `claude-haiku-5-5`, also via OpenRouter) rejects `temperature`/`top_p`/`top_k` and forced `tool_choice`, and thinks by default: no sampling parameters, structured output via `method: "jsonSchema"`, and Ask replays each tool turn's raw content (thinking blocks) unchanged (`ToolStep.raw`). Wire-level tests use the injected `fetch` in `apps/worker/src/llm/fakeFetch.ts`.
- A language picked at upload is stored as `sessions.language_override`; `transcribeNode` passes it as `opts.languageCode` and AssemblyAI gets `language_code` and no `language_detection`.
- User-facing errors are friendly sentences; raw errors go to logs only.
- Exact domain values (profiles, highlight types, statuses, fact sources, granularities, render settings) live in `packages/core/src/profiles.ts` and `schemas.ts` (and the specs) — use them verbatim.

## Skills in this repo (`.claude/skills/`)

- `digestor-run`: launch the stack, seed demo sessions, drive the UI with Playwright, screenshot.
- `pgboss-gotchas`: read before touching jobs, queues, the pipeline step runner, pauses, resume or retries.
- `vendor-contract-check`: before writing or changing a fake for AssemblyAI, Claude or yt-dlp.
- `llm-structured-output`: before adding or changing any LLM call that returns structured data.
- `digestor-ui`: before building or changing any screen or component (tokens, colours, copy, keyboard, a11y). The concept is agreed (UI concept spec); mockups in `docs/design/` are inspiration only.
- `nextjs16-gotchas`: before changing pages, route handlers, middleware, streaming routes, next.config or the web Dockerfile.
