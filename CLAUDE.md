# Digestor

Long public-interest videos (interviews, parliament, UN, trials) → subtitled clips. Turing College capstone. All TypeScript (strict, ESM), pnpm monorepo:

- `packages/core`: zod domain schemas, profiles and highlight types (`profiles.ts`), time/snap logic, subtitle text (`subtitleText.ts`), Drizzle tables + repo functions, LocalStorage, queue names and `JOB_OPTIONS`.
- `apps/worker`: pg-boss consumer, own step runner (`src/pipeline/run.ts`, position in `pipeline_runs`, one human pause: the context check; `match_record` runs before it and `match_record_late` after it, so a suggestion accepted at the pause is matched on Continue), analysis agents (topics, moments, briefing, checks), Ask, Chroma search index, AssemblyAI, Claude via LangChain, ffmpeg, yt-dlp, retention clean-up and stale-session sweep, evaluation (`src/eval`, `scripts/eval.ts`).
- `apps/web`: Next.js 16 (App Router, Cache Components, Turbopack): screens + API routes + SSE.

## The journalist flow

Stepper: Upload › Processing › Context › Briefing › Prepare › Export. Routes: `/` (Sessions: every video with where it is, type tabs, filters, clips, and the "Ask across videos" drawer; `components/Home/`, `lib/home.ts`), `/new` (upload), `/s/[id]` (Processing, Context check, then the Briefing page once `ready`: a summary card on top, then one card per topic with its moment tree, level checkboxes and Approve / Skip; `components/Briefing/`, loaded by `lib/briefingPage.ts`), `/s/[id]/prepare`, `/s/[id]/export`, `/reports`. `/s/[id]/briefing` redirects to `/s/[id]` with its query string (`next.config.ts`). The Ask drawer opens with `/` on the Briefing page and on Prepare (docked first when the session has a goal: see "AI goes first"); there are no letter shortcuts. A moment is Approved or Skipped (stored as `rejected`), or undecided; clicking the active status undoes it.
- Ask across videos (`agents/askLibrary.ts`, `components/Home/LibraryAsk.tsx`, `/api/library-ask`, table `library_ask_messages`, migrations 0028 and 0029 (`question_id`)): read-only, no approval pause, no checkpointer. LangGraph `route` (fast model, lenient schema: at most 5 of the owner's `ready` videos whose video isn't removed and whose Chroma collection exists, unknown ids ignored; one candidate skips the call; a failed call searches the newest) → `Send` one `search` per pick (k 4, `evidence()`) → `answer` (one ToolLLM turn without tools, per-video blocks with the same naming rules as Ask: `participantLines`/`loadSessionNames`, sensitive profiles confirmed names only, router summaries through `promptCard`) → `verify` (`verifyAnswer` per cited video on its own transcript, `splitBySession`). Citations `[S2 00:12:03]`; `sources` `{ label, sessionId, title }[]` stored per answer; each answer row stores its `question_id`; labels are per answer, so only earlier *questions* from the last hour are replayed (never earlier answers). The router's video list sits in a `<videos>` data block that can't be closed from inside. The drawer links a citation to `/s/<id>` and shows the time (the Briefing page has no time parameter); a source whose session is gone is plain text. Each done answer stores `not_searched` (migration 0035: `{ retentionDays, videos: { sessionId, title, reason }[] }`, written by `route` at answer time, so it shows then, not now): the owner's videos not offered, reason `awaiting_context`, `processing` (any other stage before `ready`), `removed` (`videoDeletedAt`) or `unavailable` (ready, no Chroma collection) (`listLibraryNotSearchable`; failed sessions never). The drawer shows a muted line under the answer, "Not searched: 2 videos still waiting for your context answers, 1 older than 14 days (search ends 14 days after upload), 1 still processing." (`notSearchedSummary`), with the titles under "Show which" (linked while the session exists), never an error. No indexed video: "None of your videos can be searched right now (search works for 14 days after upload).", with the same line naming why. Search down (Chroma): the job retries, then the answer fails with "Your videos can't be searched right now. Please try again in a few minutes."

- Stages (`schemas.ts`): `uploaded`, `downloading`, `preparing`, `transcribing`, `understanding`, `awaiting_context`, `naming_speakers`, `indexing`, `finding_topics`, `finding_moments`, `writing_briefing`, `preparing_preview`, `ready`, `failed`. A first analysis ends in `preparing_preview` (96) and the session becomes `ready` only when the 360p preview copy (`proxy.mp4`, its own job; `sessions.proxy_status`) is done too: `settlePreview` closes that join from whichever side finishes last. Until the copy exists the context check and Who's who play voice samples from `audio.mp3`; once the session is `ready`, `audio.mp3` is deleted and `audio_key` cleared (`releaseAudio` after the join; the daily `maintenance.cleanup` catches leftovers). Only transcription reads it. Transcription polling gives up after 3 × the video's length (at least 1 h) and the job retries; a whole-video yt-dlp download has a 4 h limit that kills its process group, and a failed download deletes its partial `original.*`; YouTube's own verdicts (private, age, live, size, unavailable, blocked, too slow) fail the session at once, a failure with no known cause is retried and fails only on the last attempt. The analysis (and Find more) never places a moment past the video's own length (AssemblyAI rounds its duration up).
- Profiles (`profiles.ts`): `parliament`, `supreme_court`, `electoral_debate`, `trial` (sensitive), `interview`, `un`, `other`. Each profile lists its highlight types; a type is `ai` or `counted` (`longest_speech`). The chip colour comes from `HIGHLIGHT_TYPES[*].tone` via `components/HighlightChip.tsx`.
- An analysis is a versioned set of topics, moments (granularity `exchange` / `passage` / `punchline`), highlights and a briefing; selections, clips and subtitle tracks are a personal layer (`owner_id`, `OWNER_ID = "owner"`). Selections belong to one analysis version's moments: after a re-analysis they no longer show (the Briefing page counts them per version), while clips and their subtitle tracks keep working.
- Queues (`packages/core/src/queue.ts`, all with `JOB_OPTIONS`): `session.start`, `session.resume`, `session.reanalyze`, `moment.check`, `track.prepare`, `track.burn`, `clip.render`, `briefing.translate`, `ask.run`, `ask.resume` (continue an Ask answer paused for approval), `ask.library` (Ask across videos; a retry may re-run a `running` answer, it changes nothing), `moment.find_more`, `session.proxy` (encode the preview copy; the runner transcribes without waiting for it), `session.names` (match a linked official record of the Câmara, Senado, Bundestag, US House or US Senate; rows are `suggested` (YouTube suggester, accepted by the journalist), `pending`, `running`, `waiting` (not published yet, `records.retry` looks again), `matched` or `failed`; at upload the runner's `match_record` step does it before the context check; the step takes over a `running` row only once it is untouched for 10 min (`RECORD_TAKEOVER_MS`), a fresher one is left to its job); scheduled in the worker: `session.sweep` (every 15 min), `maintenance.cleanup` (daily) and `records.retry` (hourly: claims `waiting` official-record rows whose `retry_at` is due, every 6 h, and sends `session.names`).
- Retention: `VIDEO_RETENTION_DAYS` (default 14) deletes `original.*`, `audio.mp3`, `proxy.mp4`, the pipeline run row (`pipeline_runs`, holds the context answers), the session's Ask threads (`ask_graph`) and its Chroma index (so Ask search stops working after 14 days); analyses, personal layers and rendered clips stay. The sweep fails sessions and analysis versions with no progress for 120 minutes, and job rows stuck for 30 minutes (below). A session waiting at the context check (`awaiting_context`) keeps its files, run row and index until it is answered. If deleting the Chroma index fails, `videoDeletedAt` stays unset and the next night tries again.
- Ask (`apps/worker/src/agents/ask.ts` tools, `askGraph.ts` graph) is a LangGraph graph per answer, thread id = the assistant message id: `START → agent → route`; `route` ends on a final answer, sends a turn with any call in `MUTATING_TOOLS` (`propose_clip`, `trim_clip`, `set_selection`, `make_clip_package`, `update_clip`, `replace_clip`) to `approve`, else to `tools` (`runTool`: validation, `evidence()`, the R31 cap) and back to `agent`. `approve` validates the changes without writing (plan mode: snapped times in the card's `summary`; a call that can only fail, or a selection beyond the cap, which becomes the bulk confirm, isn't asked), stores one `ask_actions` row of kind `tool_approval` per answer and turn (`createToolApproval`, unique on message + `payload.step`) and sets the message `waiting` in the same transaction, then `interrupt({ actionId })`. The drawer shows the card (Approve / Edit / Reject); `POST /api/ask-actions/[id]` stores the decision in `resolution` (`resolveToolApproval`, compare-and-set from `pending`: a second click or tab gets 409; Approve/Edit answer `VIDEO_REMOVED` once the video is gone, Reject still works) and sends `ask.resume` `{ actionId }`; the job claims `waiting` → `running` (`claimWaitingAskMessage`) and resumes with `Command({ resume })` (reject: the model reads "The user declined this change."). `waiting` is not job-owned: the sweep leaves it, and a card never answered stays until clicked. Checkpoints: `PostgresSaver` in schema `ask_graph` (migration 0026; `setup()` at worker start); a thread is deleted when its answer ends `done`/`failed`, at retention (`deleteAskThreads`, with the Chroma index) and with `deleteSession`. A resume whose thread is gone ends `failed` ("This answer can't continue any more."). Without a checkpointer (`scripts/eval-ask.ts`) `runAsk` uses a process-local MemorySaver.
- Ask verifies a final answer before it is stored (`agents/verify.ts`, node `verify`; never `NOT_IN_DATA`, the step-limit line or a turn paused for approval): quotes are matched word for word (normalised) against the whole transcript, and a quote whose words mostly aren't in the transcript counts as a translation and is judged as a claim; sentences citing `[hh:mm:ss]` go to one judge call (`AskDeps.judge`, fast model) on the transcript ±45 s around each time. Unsupported parts go back to the model as a "Verification: …" user turn at most `VERIFY_RETRIES` (2) times, then the answer keeps a last line "I couldn't confirm: …"; a failed judge call means "not checked", never unsupported. The result is a `verify_answer` chip, shown under the answer in the drawer, not as a source. A final reply cut off by the output limit (`TOOL_MAX_TOKENS` 16000, as structured calls) is stored as "My answer ran too long to finish. Please ask a narrower question." and never verified (Ask across videos too). Roles of voices marked "No name", and any role holding such a voice's name, never reach the Ask or library prompts, in any profile; the session facts are declared as data in the system prompt. Ask `trim_clip` snaps only the edges that changed (`snapEdges`, 1 s tolerance). The drawers keep polling every 10 s after 3 min ("taking longer than usual").
- AI goes first (migration 0036: `sessions.goal` nullable, at most 500 characters (`GOAL_MAX_CHARS`, `lib/goalInput.ts`; separate from `hint`), `clips.edit_version` integer default 0; spec `docs/superpowers/specs/2026-11-21-ai-goes-first-design.md`). `/new` has an optional "What do you want from this video?" (three chips, a muted Ask cost in the confirm estimate; the upload and YouTube routes store it). Core `startAskQuestion` (`db/personal.ts`) stores the question and a pending answer and enqueues `ask.run`: the Ask route uses it (`onEnqueueError: "rollback"`) and so does the worker's `startGoalAsk` (`goalAsk.ts`; `onlyIfEmpty` under `pg_advisory_xact_lock(hashtext(sessionId))`: no Ask message yet for the owner; `fail` keeps the question and fails the answer if the enqueue fails). `jobs.ts` calls it best effort (`goalHook`, errors logged, never failing the job) after `handleStart`, `handleResume` and `handleProxy`; it does nothing unless the stage is `ready` and there is a goal, so a session waiting at the context check starts Ask only once it is answered and ready, and a failed one never. Empty goal = no Ask message, nothing else changes. Web: `useAskDock`/`lib/askDock.ts` open the drawer by itself once after mount only on a desktop (≥ 1024 px) with a goal and not closed before (the choice is remembered per session in this browser, key `digestor:ask:<id>`); on a phone `AskDraftBanner` ("Ask has a draft for you", never a sheet over the page) shows when Ask started; Prepare has the drawer too (clip examples, `/`, the clip index stacks while Ask is docked); `AskThread` is split from `AskDrawer` and stays mounted across closes; `MadeWithAsk` tags clips whose creation event was by Ask (`clipsMadeByAsk`).
  - Tools added to Ask (`agents/ask.ts`, `askClips.ts`): `list_clips` (numbered exactly as Prepare shows them: `listClips` order, 1-based, live clips only), `get_clip_context` (transcript around a clip, `DEFAULT_CONTEXT_S` 60 s each side, at most `MAX_CONTEXT_S` 180), `update_clip` (format, title of a clip the user or Ask made, credit, or one subtitle draft language; no burn-in, approval or export) and `replace_clip` (another moment in the same clip: it keeps id, number, format, crop, credit and languages, drafts are made again, the old moment goes back to undecided; undo restores all of it), and the terminal `ask_user` (one question, 2–4 options of ≤ 60 characters, called alone before any other tool; the agent node ends the answer with the question, never verified, stored in the answer's `tool_calls`; the drawer shows the options of the latest answer as quick-reply buttons, older ones as text). `MUTATING_TOOLS` is now six (`propose_clip`, `trim_clip`, `set_selection`, `make_clip_package`, `update_clip`, `replace_clip`): all go through the `approve` card.
  - Edit version and stale cards: `clips.edit_version` is bumped by changes to start/end, format, crop, title, credit and subtitle languages added or removed, and by undoing them; never by style, renders, checks, acknowledgements or cue edits (`updated_at` is not used). A card records `clips: [{ id, n, version }]`; `POST /api/ask-actions/[id]` checks it first (`staleCardClips`): a stale card answers 409 with a stale resolution ("Clip {n} changed since this card was made. Ask again." / "Clip {n} was removed since this card was made. Ask again."), and the worker checks again before applying. The writes (`updateClip`, `applyClipUpdate`, `replaceClipMoment`) take `expectVersion` and compare it with the row's version in the same transaction (`StaleClipError`), so a manual edit is never overwritten. A manual edit landing between the worker's pre-check and a later call's write in the same card can let one change apply and refuse the other; nothing the journalist did by hand is lost. Clip events `update` and `replace` (Prepare's Undo reads "Undo Ask's change"); the Ask chip's Undo refuses ("There is nothing to undo.") once the clip was edited after that change, and Prepare's own Undo reverts the manual edit first, then the Ask change. `eval-ask.ts` prints "Asked a clarifying question: n of N".
- Spending control: every rate lives in core `cost.ts` with its basis (transcription $0.23/h, analysis $0.07/h, Ask $0.01 and Ask across videos $0.02 a question, subtitle translation $0.002 per clip minute, Find more $0.01, a briefing "Read in" translation $0.01 per language). Paid one-click actions ask first with the estimate (`ConfirmDialog` `estimate`): "Digest this video" (file: from its length; YouTube: the hourly rate, then Processing shows the estimate from `durationMs`), re-analysis (analysis only), "Clip this speech" (en/pt-BR), a For-all subtitle language; the clip package card states its translation cost; Ask inputs, Add language, Find more and the Briefing's "Read in" carry a muted price. The Briefing's "Spending" disclosure and the Sessions page's "Spent so far" (`listSpendingRows`, `sessionSpending`) compare estimates with what is recorded: only analysis versions' `usage` holds dollars; transcription, Ask, checks, subtitles, briefing translations and Find more are not metered.
- Chroma is live: one collection per session (`session_<uuid without dashes>`) with a transcript index for Ask, using local `Xenova/multilingual-e5-small` embeddings cached in `data/models` (`HF_HOME`).

## Câmara monitor (preview)

Official records of the Brazilian Câmara (deputies, plenary speeches, roll-call votes since 1 Feb 2026), separate from the journalist flow. Specs `docs/superpowers/specs/2026-11-11-camara-monitor-preview-design.md` and `2026-11-11-monitor-search-filters-design.md` (the workspace round).

The refresh also drops copies the Câmara files under the wrong deputy (`misfiledCopies`: header party/state on the day, else the printed name).
- Words used more than the chamber (migration 0027, no AI): `parl_word_counts` (deputy, party on the day or `''`, month, `pt_unaccent` stem, n) is rebuilt by `refreshWordCounts` (`db/monitorWords.ts`) in `refreshMonitor` right after the speeches and their party (speaker headers, the chair's turns inside a speech and the vocative to a chair's full name stripped, `monitorStoplist.ts` stemmed in SQL, stems < 3 letters and numbers dropped; `monitor-backfill.ts --words` rebuilds only this). `distinctiveWords` ranks by weighted log-odds against the whole chamber (`fightinWords.ts`, Monroe et al. 2008, z ≥ 1.96 and said ≥ 5 times, at most 20, z never shown), labels each stem with its most common written form, and gives a month share against the rest of the chamber (null under 300 words that month, `Infinity` when nobody else said it); under 1,500 counted words (`WORDS_MIN_TOKENS`) it is `enough: false` and the section says there isn't enough text. `WordHeat` shows levels only (`lib/monitor/wordHeat.ts`: not used / about / more ≥ 1.5× / much more ≥ 6×, neutral greys, text per cell): on the deputy page (`#words`, after the speeches) and, streamed, on `/monitor/deputados?party=X` above the list. Each word links to its speeches, exact words (`wordSearchHref` in `params.ts`): the deputy's speech search (`#speeches`, dropped by `ScrollToHash`) or, on a party's map, the landing's topic search by that party, speeches only; a month cell where the word was said adds that month's `from`/`to`.
- Search by meaning (migration 0030): the speeches' official text (summary while there is none) in chunks of whole sentences ≤ 1,000 characters, one sentence of overlap, the speaker header left out (core's `SPEECH_HEADER_PATTERN`, spoken or sent in writing) (`monitor/embedSpeeches.ts`), embedded with the local e5 model into the Chroma collection `monitor_camara_speeches` (ids `${speechKey}#${i}`, metadata `speechKey, memberId, startsAt`); `parl_speech_embeddings` records which keys are in it. Queue `monitor.embed` (daily 10:00 UTC, after the refresh, at most 2,000 speeches a run) adds new keys and deletes revised texts' old chunks; `scripts/monitor-embed.ts` is the first full run (dev: 7,899 speeches, 23,460 chunks, 38 min). The worker serves it on internal HTTP (`src/http.ts`, `WORKER_HTTP_PORT` 8790, no auth: dev publishes 127.0.0.1:8790, prod only on the compose network): `POST /monitor/search {q, k≤200}` → best chunk per speech, `POST /monitor/passages {q, speechKeys≤50, perSpeech≤10 (3)}` → sentences of those speeches' closest stored chunks, best first (for Ask the record; speeches not indexed yet are embedded on the fly, ≤ 200 chunks a call), `GET /health`; failures answer 503 JSON; `speechKeys` items must have the stored key shape (400 otherwise). The web (`lib/monitor/semantic.ts`, `WORKER_URL`, 3 s, cached an hour; after a refused connection or a 5xx the worker isn't asked for 30 s; a timeout or a 404 fails that search only) fuses it into the landing's speech search under "Best match" (not `exact=1`, not "Newest first"; the deputy page stays word-only): `hybridSpeeches` reads every word match's key, fuses the top 100 of each with `rrf` (core, k = 60, meaning hits through the filters via `filterSpeechKeys`), then the remaining word matches, and pages over that list with `speechesByKeys`; rows only meaning found are marked "Close in meaning" (the label votes and bills use), open with the summary and are counted apart (`meaningOnly`): the counts line and the section count read "N speeches · plus K close in meaning", a note says they may not be about the topic, and with no word match at all "No speech uses these words. Closest by meaning (may be unrelated):" (a gibberish query lists only those, never as matches, at most 10 (`MEANING_ONLY_MAX`) and no pager; the counts line reads "No speech uses these words · N close in meaning"). Once a topic query is in the URL, the speech filters fold into a closed `<details>` "Filters (n)" (`activeTopicFilters`) so results start above the fold. Worker down or index missing: word results plus "Search by meaning isn't available right now." Evaluation: `scripts/eval-monitor-search.ts` on `eval/monitor-search.golden.json` (speeches identified by deputy, start minute, phase and an ordinal, never by key; recall@10 words 0.41, meaning 0.53, hybrid 0.61; `docs/capstone/evaluation.md`).
- Votes and bills by meaning (migration 0031): roll calls (bill label + summary + what was voted) and signed bills with a summary (label + summary), one short text each, in their own collections `monitor_camara_rollcalls` / `monitor_camara_bills` (`monitor/embedRecords.ts`, id = the record's id; `parl_record_embeddings` keeps the md5 of the embedded text, so a changed text is embedded again and a gone record deleted). `monitor.embed` runs `embedMonitor`: speeches first, then roll calls and bills with what is left of the 2,000-item cap; the embed script does all. `POST /monitor/search {q, kind: "rollCalls"|"bills", ids (roll calls ≤ 3,000, bills ≤ 5,000: the 64 KB body; that kind's id shape), k≤200}` → `{ hits: {id, score}[] }`: only the given ids are scored (a deputy's own records after the other filters), so narrow filters lose nothing; that index not built yet → 404. The worker warms both collections at startup (`warmRecordIndexes`: a read of stored vectors and one query). The web (`recordSearch`, started beside the translation, 3 s; only a refused connection or a 5xx pauses the shared 30 s back-off, a timeout or a 404 fails that search only) builds the list with `fuseRecords` (core): the word matches always first, best first, in RRF order (k = 60) with the meaning hits so a word match meaning also found rises; then the hits only meaning found, at most 10 and within 0.03 of the best hit (`RECORD_MEANING`: e5 scores bunch at 0.75–0.9, so no fixed floor works), in meaning order. `hybridVotes` / `hybridBills` page over that list (`listMemberVotes` / `listMemberBills` `ids`) and count those rows apart (`meaningOnly`): "N of M recorded votes · plus K close in meaning"; they carry "Close in meaning" and `MeaningNote` says they may not be about the topic. With no word match they are held back (`meaningHidden`): "No vote uses these words." and a link "Show the N closest by meaning" (`vmeaning=1` / `bmeaning=1`, kept by the other sections' forms, dropped by a new search in its own), then "No vote uses these words. Closest by meaning (may be unrelated):", or "Closest matches first.", or that meaning is unavailable. Exact words: `meaning` null, word matches best first. Evaluation: `scripts/eval-monitor-records.ts` on `eval/monitor-records.golden.json` (4 vote and 4 bill queries, each scoped to one deputy, plus 2 null queries whose false positives are reported; `--sweep` for the cut).
- "Clip this speech" (migration 0032; `ClipSpeech` beside "Watch the speech", confirm dialog): `POST /api/monitor/clip { speechKey }` (`speechClipSource`) opens the speech's video moment ± 20 s (`clipSection`, clamped to the video) as a YouTube session: `sessions.source_start_ms`/`source_end_ms`, language `pt`, title and hint name the speaker (party-UF on the day) and date, the plenary linked as its Câmara record (`evento-legislativo/<id>` through `readRecordInput`), profile left to the context check; then `sendStart`. Parts over 60 min: 422. The download step passes the part to yt-dlp (`--download-sections`, https formats only with no fallback, no size cap, a time limit of 4 × the part (≥ 10 min) that kills yt-dlp's process group, since `withYouTubeCookies` holds one YouTube slot) and keeps the given title. Times in the session are relative to the part; a link back to YouTube adds `source_start_ms` (none exists yet). Only with `MONITOR_CLIP_ENABLED=true` (web; off = 403, and the opened player says why; off on production).
- The only LLM call: `lib/monitor/translateQuery.ts` in the web app turns a query into ≤ 4 Portuguese terms (OpenRouter, 10 s, cached); without `OPENROUTER_API_KEY`, on failure or with `exact=1` the words are searched as typed. The terms it adds are shown as "related terms added automatically", and rows holding the typed words together rank first (`phrase`). No AI text about a person anywhere. Code never fetches `www.camara.leg.br` pages.

## Environment

- Docker runs on **Colima** (`colima start --cpu 4 --memory 4`; this Mac has 8 GB RAM, so 8 for the VM pushed macOS into heavy swap), not Docker Desktop. `docker compose up -d` starts postgres, chroma (transcript index for Ask) and the worker; the web app runs on the host: `pnpm --filter @digestor/web dev`.
- **Never install or call ffmpeg/yt-dlp on the host** (host ffmpeg has no libass). Anything that runs them — worker code and its tests — runs in the worker container.
- API keys live in `.env` (`ANTHROPIC_API_KEY`, `ASSEMBLYAI_API_KEY`, `OPENROUTER_API_KEY`, `API_DATA_GOV_KEY` for US House/Senate records, optional `BUNDESTAG_DIP_API_KEY`); they may be empty. `LLM_PROVIDER=anthropic|openrouter` (default anthropic) picks the LLM vendor (`apps/worker/src/llm/provider.ts`); the key it needs is the one a missing-key failure names. Every structured call goes through `StructuredLLM` and Ask through `ToolLLM`, so a provider is one adapter pair; analysis versions record provider-qualified model ids (`StructuredLLM.modelIds`). Changing `.env` needs `docker compose up -d worker` (restart doesn't re-read it). The worker starts without them and fails a job with "`<VAR>` is not set on the server." when first needed. `APP_PASSWORD` empty = password gate off.
- YouTube from a server IP hits a bot check: `YTDLP_COOKIES_FILE` (a cookies.txt in git-ignored `./secrets/`, mounted read-only at `/secrets`) gets past it; see `docs/deploy.md`. yt-dlp runs that use it go through `withYouTubeCookies` (`youtube/cookieJar.ts`): one at a time, on a live jar in `<DATA_DIR>/.youtube/` that keeps YouTube's refreshed cookies and restarts from a new export. A block that exits 0 (caption fetch) is detected (`blocked`) and fails, never "no captions".
- The worker container bind-mounts the repo and runs `tsx watch`; after editing worker code over the Colima mount, `docker compose restart worker` if the change isn't picked up.

## Conventions that bite

- `@digestor/core` is client-safe; DB, repo, storage and migrate come from `@digestor/core/server`. Never import `/server` from a client component.
- Merge (`mergeClips`) is only for clips that overlap partly or touch (never a gap, never one clip inside the other: `contained`); it keeps the earlier clip, soft-deletes the later one and stores its moments in `clips.merged_moment_ids`; Undo restores both; a clip is dismissed when any of its moments is not approved.
- Relative imports inside `packages/core` use `.ts` extensions (Turbopack can't map `.js` → `.ts`); the worker uses `.js`. Keep each package's convention.
- The DB stores storage-relative keys (`<sessionId>/original.mp4`), never absolute paths; each process resolves them against its own `DATA_DIR` (`LocalStorage.pathOf` for reads, `resolve`, which creates the folder, for writers).
- Uploaded files are saved as `original.<ext>`; user filenames never reach ffmpeg. The upload/YouTube note (hint) is capped at 2,000 characters (friendly 400).
- Concurrency is guarded in the database, not by pg-boss:
  - stage changes via `transitionStage` (compare-and-set);
  - `confirmClips` and `claimAnalysisVersion` run under `pg_advisory_xact_lock(hashtext(sessionId))`;
  - renders and burns use claim/finish compare-and-set (`claimClipRender` / `finishClipRender`, `claimTrackBurn` / `finishTrackBurn`); a burn or render whose cues, bounds, credit or subtitle style/position (`burnSignature`) changed meanwhile is marked `stale`;
  - Ask actions use `resolveAskAction` (compare-and-set), and Ask undo only reverts what the call itself set.
- `singletonKey` is a no-op on our standard queues: never rely on it to dedupe; claim in the database first, then send. `requestTranslation` is a claim too (a new or failed row only); the translations route sends a job only when it claimed.
  - `moment.check` is claimed with `claimMomentCheck` (checks null and no claim younger than 10 min); a failed send or a job that gives up calls `releaseMomentCheck`. Ask answers are claimed with `claimAskMessage` (`pending` → `running`), resumed ones with `claimWaitingAskMessage` (`waiting` → `running`); a retry that finds `running` fails the message instead of repeating tool calls, and a retryable error puts it back to `pending` (`ask.run`) or `waiting` (a resume); the retry continues from the last checkpoint (`ask.run`: only while the thread wrote nothing, else from the question).
- Subtitle tracks record the clip range they were built for (`built_start_ms` / `built_end_ms`). Any bounds change (trim, extend, undo, Ask `trim_clip`) marks other-range tracks `outdated` and clears approval in the same transaction; outdated tracks have no SRT/VTT, fail the checklist and are rebuilt through `POST /api/clips/[id]/tracks` (R27).
- Moment checks describe the moment's bounds: they count for a clip only while its bounds equal the moment's (`checksForClip`); any bounds change resets `warningsAck` (R28).
- The sweep also fails job rows whose job died: translations `pending`, tracks `preparing`, renders and burns `queued`/`rendering`, "Find more" requests `pending`/`running`, record fetches `pending`/`running` (`waiting` and `suggested` are not job-owned), answers across videos `pending`/`running` (`library_ask_messages`), preview copies `pending`/`running` (`sessions.proxy_status`), Ask answers (`ask_messages`) `pending`/`running` with no live `ask.run` or `ask.resume` job (`waiting` is not job-owned), untouched for 30 min with no live job matched on pg-boss job data (R32). New job-owned rows belong there too.
- The credit typed once is remembered: `clips.credit_set_at` is set only when a clip's credit changes, and `insertClip` copies the most recently set credit to new clips. Export's "Download all" is `GET /api/sessions/[id]/download?choice=burned|files|plain` (`check=1` answers `{ files }` as JSON), a zip built from stored files and cue-rendered SRT/VTT only; nothing is rendered or encoded there.
- A made video (plain render or burned-in) is offered on Export, per clip and in "Download all" (`check=1` too), only while that clip passes `exportChecklist` now (`exportRows` `cleared`), for every clip, not only packages: a clip rendered earlier whose checklist fails today (an outdated track, a new warning, a protected person) disappears from Export and the zip until it is fixed. SRT/VTT drafts stay downloadable. The export POST also blocks dismissed clips (`failing: ["dismissed"]`).
- Once a session's video is removed (`videoDeletedAt`), kept clips are frozen: clip edits, undo and track edits/approve/burn and adding, retrying or rebuilding a language (`POST /api/clips/[id]/tracks`; Prepare hides those buttons) answer 409 with `VIDEO_REMOVED`; acknowledgements and downloads still work (R30).
- Ask changes nothing without the journalist's approval (the `tool_approval` card), and makes at most 3 approved changes per question, counting each moment of `set_selection`, each `propose_clip`, each `trim_clip`, each `update_clip`, each `replace_clip` (one change each) and each `make_clip_package` (the whole package is one); beyond that selections become a bulk confirm action and clip calls are refused.
- Clip packages ("3 clips on Ukraine for Instagram"): `find_clip_candidates` (read-only: analysis moments matching the topic, then transcript search hits, snapped to sentences; `count` default 3, at most 5, plus 2 extra to choose from) → `make_clip_package` (1–5 clips, one format, optional subtitle drafts in one language; the approval card lets the journalist untick and edit clips). Approved, it creates a personal moment (approved) and a clip per item, sets the channel credit, claims and sends one `track.prepare` per draft, one `clip.render` per clip and one `moment.check` per moment (`requestMomentCheck`, as `propose_clip` does; claim in the database first; a failed send gives the claim back). So a package renders *before* the export checklist; in a sensitive profile (`trial`) it never renders (drafts only; the journalist renders from Export once the checklist, protected persons included, passes). Burned-in subtitles always wait for approval on Prepare. Tool output built from transcript-derived text (search hits, transcript, moment titles and reasons) goes through `evidence()` (R31).
- Subtitle SRT/VTT downloads are rendered from the track's cues on every request (never stored files), and drafts stay downloadable; burn-in needs per-language approval.
- Trim: the server snaps only the edges that changed to sentence boundaries (an untouched edge, within 100 ms of its stored value, stays verbatim). `PATCH /api/clips/[id]` with `free: true` (Alt/Option drag or Alt+arrows in the UI) saves the exact position; the clip then carries `midSentence` (checks are null, so it needs `warningsAck`).
- Approved moments are never hidden by filters: the briefing footer reads "N approved · M hidden by filters" with a "Show hidden" button.
- AI and normal cuts snap to sentence boundaries (sentence ends, or a pause inside a very long sentence); an Alt cut is saved as is and carries a mid-sentence warning. Every boundary except a deliberate Alt cut goes through `snapRange`/`snapEdges`; Extend, Ask `trim_clip`, normal drags and the typed fields still snap.
- Claude 5.5 (`claude-sonnet-5-5`, `claude-haiku-5-5`, also via OpenRouter) rejects `temperature`/`top_p`/`top_k` and forced `tool_choice`, and thinks by default: no sampling parameters, structured output via `method: "jsonSchema"`, and Ask replays each tool turn's raw content (thinking blocks) unchanged (`ToolStep.raw`). Wire-level tests use the injected `fetch` in `apps/worker/src/llm/fakeFetch.ts`.
- A language picked at upload is stored as `sessions.language_override`; `transcribeNode` passes it as `opts.languageCode` and AssemblyAI gets `language_code` and no `language_detection`.
- User-facing errors are friendly sentences; raw errors go to logs only.
- Exact domain values (profiles, highlight types, statuses, fact sources, granularities, render settings) live in `packages/core/src/profiles.ts` and `schemas.ts` (and the specs) — use them verbatim.
